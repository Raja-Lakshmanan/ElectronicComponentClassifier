[SECTION 5] VERIFICATION OF CRITICAL AUDIT ITEMS
------------------------------------------------------------------------------------------
  1. Macro F1 & Zero-Division Behavior:
     - Both train_v2.py, train_v3.py, and diagnose_predictions.py implement:
       * When sklearn is installed: f1_score(..., average='macro', zero_division=0)
       * Pure Python fallback: computes per-class precision and recall;
         if (precision + recall) == 0, sets F1 = 0.0 (prevents division by zero);
         then takes arithmetic mean across all 10 classes.
     - VERDICT: [PASS] Mathematically exact harmonic mean with robust zero-division handling.

  2. Class Index Alignment across Splits:
     - ImageFolder uses Python's os.listdir() sorted alphabetically.
     - model.CLASS_NAMES is alphabetically sorted from 'capacitor' (0) to 'transistor' (9).
     - Every script (train, train_v2, train_v3, evaluate, diagnose_predictions) enforces
       verify_class_order(dataset.class_to_idx, CLASS_NAMES) before any forward pass.
     - Dataset audit confirmed all 10 class directories exist in train and val with exact names.
     - VERDICT: [PASS] Exact 1-to-1 alignment guaranteed across all scripts.

  3. Scheduler.step Call Site & Learning Rate Logging Timing:
     - Scheduler: ReduceLROnPlateau(mode='min', factor=0.5, patience=3)
     - Call site: scheduler.step(val_loss) is called after validate() completes.
     - LR Logging: curr_lr is sampled at the beginning of each epoch (before training).
       Thus, the logged LR in training_history CSV reflects the actual learning rate applied
       during gradient descent in that epoch.
     - Checkpoint Timing: save_checkpoint is called *after* scheduler.step(val_loss).
       The saved scheduler_state_dict has already updated internal counters for that epoch.
     - In V3 history: Learning rate stayed constant at 0.000300 across all 30 epochs because
       validation loss decreased steadily (from 2.1768 to 1.8609) without stagnating for
       3 consecutive epochs.
     - VERDICT: [PASS] Proper placement and correct causality.

  4. Final Per-Class Report & Macro Metrics Label Ordering:
     - In train_v3.py: validate() collects all_preds and all_labels sequentially.
     - compute_detailed_metrics iterates for c in range(NUM_CLASSES) indexing CLASS_NAMES[c].
     - The per-class table and macro_f1 average use the identical prediction array and label order.
     - VERDICT: [PASS] Completely consistent.


[SECTION 6] FINDINGS CATEGORIZATION
------------------------------------------------------------------------------------------

  CATEGORY A: CONFIRMED CODE BUGS
  ----------------------------------------
  None found. All scripts compile, adhere to verified class indices, handle OOM,
  properly guard zero division, and protect test-set isolation.

  CATEGORY B: ARCHITECTURAL & FORMAT INCONSISTENCIES
  ----------------------------------------------------
  1. Checkpoint Dictionary Schema Evolution:
     - V1 checkpoint has 9 keys (no scheduler_state_dict, val_loss, val_macro_f1, class_weights).
     - V2 and V3 checkpoints have 14 keys.
     - Status: Non-breaking; evaluate.py and diagnose_predictions.py use backward-compatible .get().
  2. Validation Loss Computation Nuance:
     - V1 computed val_loss using unweighted CrossEntropyLoss.
     - V2 and V3 pass the weighted criterion into validate(), computing weighted val_loss.
     - Impact: While internally consistent for ReduceLROnPlateau in each pipeline, V2/V3 val_loss
       cannot be directly compared in absolute value against V1 val_loss.

  CATEGORY C: CONFIRMED MODELING ISSUES (Root Cause of V3 Performance)
  --------------------------------------------------------------------
  1. Severe Under-Training with LR=0.0003 at 30 Epochs:
     - In V3, initial LR was reduced from 0.0010 to 0.0003 (3.3x lower).
     - In V2 (LR=0.0010), by epoch 30 train loss reached 1.5214 and train accuracy reached 48.32%.
     - In V3 (LR=0.00030), by epoch 30 train loss was still 1.9070 and train accuracy was only 35.10%.
     - At epoch 30, V3 was only at the training stage that V2 reached around epoch 12!
     - Because the network was under-trained, feature representations were not yet discriminative,
       yielding 39.77% val accuracy and 0.2683 macro F1.
  2. Early Stopping Did Not Trigger Because V3 Was Still Progressing:
     - V3's macro F1 was actively climbing at the end: Epoch 28 (0.2297) -> Epoch 29 (0.2530) -> Epoch 30 (0.2683).
     - Epoch 30 was the best epoch of the entire run, proving the model had not converged or plateaued.
     - Recommendation: If retaining LR=0.0003, train for 50-60 epochs; alternatively, use LR=0.0006-0.0008.
